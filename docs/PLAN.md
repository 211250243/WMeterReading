# 多水表批量识别：问题清单与训练准备

更新：2026-09-23。真实场景是很多块水表，各自正上方固定正向摄像头，批量读取字轮和全部读数小表盘。用户要求当前不考虑强光，已从计划删除局部强光/可读性判断、专项增强及采集侧改造。该模块此前未实现，无运行代码或权重需要删除。

迁移准备已开始执行，最新完成项、运行证据与剩余条件见第7节。旧精度结果不因训练代码修改而自动更新。

## 1. 当前确定的流程

批量原图 → 自动检测字轮和小表盘 → 精确范围裁剪及必要小角度校正 → 字轮识别/单盘指针识别 → 全图布局与倍率依据确认 → 按可信顺序进行指针上下文解码 → 字轮与指针联合进位计算 → 输出完整读数、字轮与逐盘结果。

表型倍率可与单盘识别并行，但必须在上下文进位解码前确认。每张图独立处理，不需要参考图建档、图像配准、历史序列、人工ROI、文件名中的读数或标签答案。保留图片可读取、区域有效、缺位/冲突及模型输出检查，这些不是新增可读性模块。

固定正向降低整体方向难度，但各小盘的零刻度、倍率和旋向不能省略。不同水表不共用未经验证的布局。保留已有有序四边形监督，不新增逐位数字框、针尖或像素掩膜任务。

目录边界不变：references外部源码、meter_reader自研、data数据、weights权重、outputs产物、docs短说明。旧目录及人工核对记录不改；不建审计、注册中心、测试平台等外围设施。

## 2. 到底有几个训练任务

| 功能块 | 当前实现/权重 | 本项目训练入口 | 本轮选择 |
|---|---|---|---|
| 字轮与小盘定位 | RT-DETRv2-R18，detector/meter.pt | detector：已实现并在CPU运行 | 保留，修正训练/验证后做640起步的全参数微调 |
| 精确范围/方向 | RegionNet，geometry.pt；附带旧倍率/表型头 | geometry：已实现并在CPU运行 | 不锁定自制网络；先检查直接裁剪对照，将联合检测四角列为首个结构替代候选，见第6节 |
| 字轮识别 | OpenOCR SVTRv2，wheel/meter.pt | wheel：已实现并在CPU运行 | 保留，修改微调方式及标签处理后全参数适配 |
| 指针识别与上下文 | CNN im.pkl + Transformer tr.pkl | 无pointer任务 | 先复用作者权重，稳定裁剪后检查，再决定是否适配微调入口 |

结论：4个业务功能块，不是4个已准备好的训练任务。本项目当前可训练3项；指针块内部有2个网络。按当前实现共有5个神经网络实例，不等于5项都要重训。透视变换与Decimal组合属于算法，不训练模型。

上游references/WMeter-Reader/train.py存在，但默认加载CNN并在no_grad下使用，主要训练Transformer；同时写死LMDB/权重相对路径、CUDA及部分参数，并依赖本项目requirements未声明的训练依赖。不能把它当成已经适配本项目、能直接训练整个指针模块的入口。

当前可运行的训练任务仍是detector、geometry、wheel三项。此次调研调整后，不再预先要求把三个旧模型全部长时间重训：先完成第6节的裁剪对照，再决定是否合并定位与四角。一次只验证一个替代方案，胜出后才切换主路径。指针是否追加训练取决于正确裁剪上的失败；若微调CNN导致分布变化，还要检查/适配上下文模型。表型倍率是必须补齐的算法职责，不默认增加一个新网络，也不能因合并模型就省略。

## 5. 实施顺序

先修标签、输入、倍率/进位与验证代码 → 比较自动框直接裁剪和现有几何裁剪 → 在5090完成定位/四角方案选择及训练 → 检查自动裁剪 → 字轮微调及指针诊断 → 确有必要时适配指针微调 → 真实原图整表批量验证。

只用少量真实图、裁剪可视化和直观进位例子验证，不建额外测试平台。公共同机位相似图可能使指标乐观，能可靠按物理表分组时分组核对；不使用预测或个人记录直接生成训练真值。GPU可加快训练，但不会修复错误标签/倍率/进位逻辑。

## 6. 四个功能块的调研结论与选择（2026-09-23补充）

依据为作者论文/仓库、工业厂商公开示例和当前项目错误，来源及适用边界见[REFERENCES](REFERENCES.md)。没有同一批水表上的充分比较，不能称当前组合或候选为“效果最好”。商业产品公开功能也不能证明内部使用哪种网络或某算法占行业多数。

### 定位与精确范围：先解决错误裁剪，再决定是否合并

- RT-DETRv2-R18保留为已有检测基线。320输入、冻结主干、全量训练不足，不能据当前效果判定该架构不行。先统一推理/验证，以640起步检查完整范围和小盘像素。
- 当前RegionNet是自制小型CNN直接回归8个坐标，不是经过水表公开对比验证的强基线，也是已确认的主要误差来源。优先比较同一自动框的直接裁剪与四角裁剪，判断校正究竟改善还是损害识别；直接裁剪只用于已正向区域的对照，不能把任意盘的图像朝上当成作者模型要求的零位方向。
- 首个结构替代候选采用**检测+4个有序关键点联合预测（Ultralytics Pose）**，复用已有区域四角，联合输出两类区域和四角，减少粗框再裁剪给第二网络所造成的输入偏差。这是针对本项目的工程判断，不是已证明比两阶段准。先选单一中等规模配置，不同时实现多代YOLO。
- 接入前核对四角索引是否表达一致的读数方向。不能按图片左上角重新排序，也不能直接使用人体左右翻转配置；第一版关闭镜像增强。普通圆形边界、像素掩膜或OBB都不能单独确定零刻度、旋向或消除180度歧义。四角表示裁剪范围，不等于逐像素分割，也不提供针尖监督。
- 四角数据转换已在迁移准备中实现（第7节）；联合模型训练/推理适配目前**未实现**。替换RegionNet时，其旧倍率/表型头的职责须另用全图布局及可靠倍率证据承接，不能随旧网络删除。公共标签不足的型号仍明确未支持。
- 若最终保留框检测而检测本身仍是瓶颈，仅以**D-FINE-M**作为下一项框检测对照。其通用COCO表现和框回归设计有参考价值，不自带水表方向或进位；不同时引入RT-DETRv4、多个YOLO及D-FINE。

### 字轮：保留SVTRv2，先适配翻字和数字任务

- SVTRv2有公开训练实现和通用文字识别实验证据，现有53.2%整行匹配不能解释为架构上限。先全参数微调、合理保持长宽比、匹配自动裁剪误差，核对字符字典及CTC输入/输出长度。训练后可见字符和最终累计读数仍分别保存。
- 核实WMeter5K的v语义后再设计过渡状态目标，不能删除v或用整表答案改写可见字轮。借鉴SCUT-WMN将翻字中间状态单独编码的思路，不照搬其末位加0.5规则，也不把两套数据符号假定为同义。现有标签无法确定的状态不伪造细分类标签。
- 首轮仍用整行标签，不要求逐位框。现有监督不足以解决的业务字体/翻字问题，后续再明确需要哪些真实标注。
- 完成上述适配后，若字轮仍是瓶颈，只加**PARSeq**一次对照。现有OpenOCR源码已有PARSeq配置，可优先检查复用；尚无本项目适配权重或已验证训练入口，不另搬完整OCR应用。通用语言上下文对任意数字串的优势需要实测。

### 指针：保留WMeter多盘上下文方案

- WMeter-Reader专门处理水表过渡读数，数据也来自附加摄像头拍摄的水表，与本任务接近。其上游demo先依赖区域标注裁剪，不能把上游效果当成自动整图效果。
- 先在准确裁剪和可信位权顺序下分别检查单盘CNN与上下文Transformer；确实还有系统误差，再适配相应微调入口。既不盲目替换，也不保证现有权重永远够用。
- 指针/刻度分割、中心/针尖关键点和角度换算是公开工业仪表方案中的另一类路线。OpenVINO工业示例和ETH压力表方案可参考，但本项目没有针尖/针线/刻度的对应监督；单盘角度准确也不自动解决多盘倍率、临界进位及字轮衔接。当前不新增该训练分支。

### 如何选择、最终训练几项

1. 复用同一批原图和作者划分，先保存自动框、四角、实际识别裁剪及逐项读数；人工只查看诊断，不向正常推理提供坐标/答案。
2. 比较漏盘/多盘、范围IoU、语义方向错误、字轮整行匹配、指针序列及整表完整正确/错误/未输出。真值裁剪只作独立诊断；所有失败图计入分母，不以少量可视化或框AP宣称生产准确率。
3. 先选择定位/四角方案，再固定它微调字轮；不同模型使用相同标签、划分与可比较的训练预算。小样本用于定位错误，选定方案仍需跑现有完整验证集和业务原图；无可信业务真值时不报业务准确率。不搭建新测试平台。
4. **当前是3个可运行训练任务。**若联合定位四角方案经验证胜出，则定位/校正合为1项，加字轮共2项主要微调任务；指针是否追加由错误决定。倍率识别职责仍存在，其实现若确需新学习模块须另行明确，不能预先保证总共只训练2个。

选型调研本身仅更新方案与来源，随后迁移准备执行情况见第7节。强光、人工ROI建档、参考图配准与历史序列均不加入当前主流程。
