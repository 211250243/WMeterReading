# 识别误差与处理顺序

目标是从原始照片自动得到准确完整读数。人工核对只能用于开发时查看错误，不能作为最终识别能力的替代。本次是针对已有代码、53张业务输出和96张公共验证输出的诊断，没有更改权重，也没有通过降低阈值伪造改善。

## 已确认的问题

1. 检测训练不足且评价太宽松。现有检测器为320分辨率、冻结主干，只有一轮全量训练。96张公共图中658个指针盘，有607个粗框达到IoU 0.5，但只有361个达到0.8。粗框覆盖到目标不等于适合精确读数。
2. 四角校正是主要失败点。上述指针中只有132个最终四角达到IoU 0.8；585个成功输出四角的匹配区域中，74个方向误差超过15度。业务图检测出的54个字轮中34个校正失败，193个指针中98个失败。这些分母是检测出的区域，不是真值目标数。
3. 校正训练与推理输入不一致。训练使用真值框扩边后的裁剪，增强只有90度旋转与亮度，没有模拟实际检测框偏移、尺度误差和透视变化。同一组629个匹配公共区域，使用真值框时615个位权正确，使用检测框时581个正确（校正拒绝也计为不正确）。这组诊断中的真值框不进入正常推理。
4. 局部小网络同时预测角点、倍率、整表类型，缺少可靠全局证据。业务首图实际含字轮与4盘，一个局部裁剪却以约99.8%分数判成8盘全指针表。真值裁剪上接近99%的分类指标不能证明业务整图可靠。角点MSE回归在方向不确定时可能向平均形状收缩，与实际失败现象一致；这部分是机制解释，尚未通过专门实验量化。
5. 识别器自身也未达标。使用真值字轮裁剪时，235窗口仅125个可见标签完全正确；现有8轮微调冻结了编码器。指针在32张真值裁剪序列上28张正确，自动裁剪/顺序误差会进一步恶化。残缺指针序列仍可进入当前上下文解码器，其输出分数不代表完整读数可信。
6. 完整读数算法仍缺关键部分。v尚未可靠解释；当前0.5/0.02分界只用于保留提前翻字/临界候选，不是验证过的完整翻字进位算法。不能把这些保守规则当作已完成整表识别。

当前实现是检测框和有向四角裁剪，没有像素级分割。现有四边形标签足以继续改善范围和方向，当前不要求新增针尖、逐位框或掩膜标注。

## 修复顺序

1. 暂停扩展人工复核页面，将准确完整读数重新作为实现优先级。
2. 先改定位校正：检测器在640起步做全参数微调；分开约束长条字轮和小表盘的几何特征；方向与形状分别验证；加入连续旋转、透视和检测框扰动。必须同时检查自动框上的裁剪完整性、方向和后续识别，不能只看真值框指标或IoU 0.5。
3. 在确认裁剪正确后改善识别：字轮解冻适配，保留可见字符/翻字状态；指针核对预处理、方向和位序，再决定需要微调的部分。分别保存正确裁剪与自动裁剪结果，定位真实损失来源。
4. 重做倍率确认：利用全图布局和倍率文字，识别有依据的表型；不继续依赖一个局部小网络自由猜整表类型。先确认盘数、方向、位权及顺序，再进行上下文进位解码。
5. 明确v语义并实现字轮与低位指针的联合进位消歧，逐个核对提前翻字、9→0和重复位权实例。现有阈值拒绝规则不能替代这一环节。
6. 最后将页面改成以完整读数为主、字轮与各盘依据为辅的结果展示。仍不能确定的图如实显示失败，开发期诊断信息折叠。

先修正实现与训练目标，再使用GPU充分训练。GPU能缩短训练时间，不能自行解决表型猜错、裁剪分布不一致和缺失的进位逻辑。继续优先使用公共数据；业务标注应由修复后仍存在的实际错误决定。

量化诊断：`outputs/diagnosis/region_quality.json`、`outputs/diagnosis/crop_shift.json`。

## 开始修正后的状态（2026-09-22）

已修正指针上下文解码的入口：必须通过全部检测区域的校正状态、盘数、字轮数量、连续且唯一的位权范围、表型一致性和倍率/表型分数检查。缺盘、错位或不确定时只运行单盘CNN，保留原始类别，不再把残缺序列送入进位解码器。结果增加 `pointer_context_status` 说明是否解码及原因。这些检查不能证明局部表型模型已经可靠，不能代替后续全图布局/倍率识别。

重新推理了2张公共图片和2张业务图片：两张公共图的完整结果保持不变；两张业务图原先分别对1盘、2盘输出上下文数字，现在保留单盘类别并停止无依据的上下文解码，完整读数仍为空。直接CNN类别与原模型一致，分数最大差异约3.3e-7。缺盘、重复位权、范围外位权、低倍率分数、校正失败、字轮数量冲突的直观例子也已核对。结果保存在 `outputs/correction_sequence/`，详细对照为 `change_check.json`。未扩大为精度评测，不宣称识别准确率提高。

训练资源已成为当前阻塞点，按用户要求暂停后续训练和算法改造。当前 PyTorch 为2.6.0+cpu、CUDA不可用，系统查询到AMD Radeon核显和虚拟显示适配器。用真实训练图片、640分辨率、batch=2、4线程做全参数前后向及优化器更新：1次预热后3次计时，中位数1.676秒/批。3975张每轮估算约56分钟，40轮约37小时；不含验证、校正/字轮训练及多次改法比较。它不是内存报错或CPU完全不能运行，而是完整修正所需的训练迭代无法在本次交互中完成。计时仅更新内存模型，没有保存或替换权重。测量见 `outputs/diagnosis/cpu_training_cost.json`。

继续需要可用CUDA的GPU训练环境及其接入方式；显存和batch在该设备实测后确定。恢复时先修正几何监督/增强和全图倍率依据，再训练及比较真实自动裁剪后的读数，不能直接把原训练命令跑久就宣称修复。当前范围、角度、字轮识别、表型倍率与翻字消歧仍未修好。
